# Experiment evidence

The active experiment is fixed-spawn1v1 self-play under the [staged registration](../docs/duel-protocol.md). [Nine-cell calibration evidence](duel-fixed-v1/calibration/selection.json) and its [resolution](../docs/amendments/2026-10-23-duel-calibration.md) precede reward pilots; no new learning-quality claim is made before held-out evaluation. The [failed zero-update launch](duel-fixed-v1/launch-failure/) remains evidence. Each future stage needs a separately authorized budget.

Completed exploratory pilots: [R0](duel-fixed-v1/pilot-R0.md) improved primary validation score by 0.01237; [R1](duel-fixed-v1/pilot-R1.md) by 0.06315. Both failed the registered 0.10 selection gate. Their random-opponent wins increased, but neither beat the moving scripted benchmark. Identical actor/critic initialization and equal 1,245,184-step budgets are verified in the raw assessments. These are single-seed validation findings, not three-model confirmation or final-test results. R2 remains the next registered candidate.

The original six-run5v5 experiment is **deferred**, with [negative learning audit results](learning-audit/summary.md), [ten hardware probes](performance/summary.md), original checkpoints and interruptions preserved. Its frozen [protocol](../docs/protocol.md) and deadlines are not extended. The older [verification summary](verification/summary.md) and [PDF](verification/paper.pdf) report CPU/CUDA smoke checks: both initial/final smoke evaluations scored0.167 over24 rounds. Those are pipeline checks, not improved tactical competence.

`uv run csrl report --input runs/duel-fixed-v1 --output reports/duel-fixed-v1` creates Stage A per-run reports, an aggregate comparison and a PDF naming Libor Burian. Inspect every generated numerical claim against raw records, add measured interpretation/plots as appropriate, and visually verify the PDF before publication. Generating a report does not make an unfinished evaluation complete. Source definitions are shared in the [bibliography](../docs/sources.md) and [evidence index](../docs/evidence-index.md).

Implementation verification before training: simulation, baseline, learning-interface, and renderer tests; native 3D screenshots; exact rendered/headless replay comparison. These validate software behavior, not the learning hypothesis.

[Engineering verification notes](verification-notes.md) record historical issues, fixes, throughput measurements and smoke limitations. Current release gates are in the [Stage A acceptance ledger](../docs/acceptance-stage-a.md). Model-level uncertainty concerns independently trained seeds; match intervals condition on the specific checkpoint. Fixed deterministic trajectory repeats are not independent evidence.
