# Shooter RL: architectures, algorithms, inputs and outputs

Reviewed 2026-10-23 after the duration/entropy results, in response to the user's request to reconsider all four design choices. This is a literature-informed engineering decision, not an experiment showing that another system's architecture is optimal here. These projects report learned self-play without human demonstrations as their training method; their human/scripted evaluations must not be confused with training data. MiniStrike continues to prohibit imitation, pretrained gameplay weights and scripted training opponents.

## What this changes here

The implemented Stage A baseline has 192 scalar inputs (four 48-field frames), a 2×128 tanh actor and a separate 2×256 tanh critic. Its five categorical heads have sizes9/5/5/2/2: movement, yaw, pitch, fire and reload, giving 23 logits and 900 possible combinations. Inputs contain own state, public ray geometry and visible player coordinates; enemy health and hidden dynamics are masked. These are code-derived facts: [observation](../src/ministrike/sim/observation.py), [match specification](../src/ministrike/sim/specs.py), [model](../src/ministrike/learning/models.py), [decoder](../src/ministrike/sim/constants.py). There is no image encoder because the actor does not receive pixels.

**Next intervention: observer-coordinate inputs, `A-DIAG-EGO-R1`.** Unity's [observation guidance](https://unity-technologies.github.io/ml-agents/Learning-Environment-Design-Agents/#vector-observation-summary-best-practices) recommends normalized, relative position features. Our existing positions are already relative displacements, but in world axes. We test rotating those same visible displacements into the observer's right/up/forward axes. This provides a geometric inductive bias without adding information, parameters, aiming assistance or a changed reward. A smaller function approximation burden is a hypothesis; only the registered comparison can support a performance claim. [Exact intervention and falsification](amendments/2026-10-23-egocentric-diagnostic.md).

PPO remains fixed during that comparison. Sample Factory's V-trace corrects asynchronous policy lag; MiniStrike currently collects synchronously from one frozen rollout policy per update. Switching to APPO now would change both the algorithm and execution system. That is a separate comparison, not a one-line loss replacement. TorchRL already supplies our [PPO/GAE implementation](https://docs.pytorch.org/rl/stable/tutorials/multiagent_ppo.html).

Further architecture, algorithm and output changes are allowed by the user's latest steering but require separate registrations. The [roadmap](experiment-roadmap.md) now includes actor-capacity, recurrence, observation representation, action-resolution and APPO comparisons. A wider MLP is plausible, but the existing evidence does not identify insufficient capacity. GRU memory is plausible when visibility is lost; sequence minibatches and hidden-state resets must be implemented correctly first. Finer aim bins are plausible: the current smallest nonzero yaw step is0.08rad (about4.58degrees), coarser than the cited Doom control. This does not prove a decoder bug or justify removing learned pitch. These alternatives remain provisional and have no allocated run until their controls, seeds, exact settings and remaining allowance are published.

No source code from these projects is copied. We reuse installed TorchRL/PyTorch APIs; this review and the coordinate transform are original. See the [shared bibliography](sources.md) for claim boundaries and the [evidence index](evidence-index.md) for measured MiniStrike results.
